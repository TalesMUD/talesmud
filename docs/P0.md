# Aethermoor Door — P0 runbook

Same `tales` binary as Veilspan. Door mode is a second process: `presentation=door_tui`, `ruleset=daily_menu_rpg`, its own port, and its own SQLite file. Do not point this config at the Veilspan database.

## Start the door instance

From the engine repo root:

```bash
mkdir -p data
export DOOR_SESSION_SECRET=dev-door-secret   # or omit; the process creates data/door.session.key
go run ./cmd/tales -config config/door.yaml
```

`make door` does the same thing.

- HTTP and WebSocket: `http://127.0.0.1:8020`
- Browser TUI: `http://127.0.0.1:8020/door/` (the root path redirects there)
- Database: `data/aethermoor-door.db` (gitignored)
- World pack: `/home/clawd/dev/talesmud-door/worlds/aethermoor-door` (Doorkeeper screens and ANSI)
- Daily reset timezone: `Europe/Berlin`
- Forest fights per day: 25 (`forest_fights` in `daily_resources`, not a quest tag)

`GET /api/mode` reports `presentation`, `ruleset`, and `auth` so you can see which process you reached.

## Start classic Veilspan beside it

Leave the door process running. In another shell, without `-config`:

```bash
PORT=8010 SQLITE_PATH=talesmud.db go run ./cmd/tales
```

That process stays `presentation=classic`, `ruleset=classic_mud`, Auth0 (plus guest tokens). It does not mount local password registration.

## Play the P0 loop

1. Open `http://127.0.0.1:8020/door/`.
2. Create an account (username, email, password). The password is stored as Argon2id. The browser keeps the session token in `localStorage` under `aethermoorDoorToken`.
3. Name a warrior, pick how the square should address them, and pick Gravebound, Veilcaller, or Cutpurse.
4. Town hotkeys from the pack: `(F)` Ashwood, `(H)` healer, `(B)` vault, `(S)` armory, `(Y)` stats, `(Q)` quit hint, `(?)` help.
5. In the Ashwood, `(A)` spends one daily fight and strikes. `(R)` runs. `(H)` on the healer mends for coin. `(D)` / `(W)` at the vault move coin. State survives a reload.

The page is an 80×25 xterm.js surface. The server sends full ANSI frames (`type: door_frame`) on the existing `/ws` socket. The client answers with `{"type":"door_key","key":"F"}`. Amounts and the warrior name are a line ended with Enter (`accepts: ["line"]`).

## Password reset

`POST /api/auth/forgot` with `{"email":"..."}` always answers `{"ok":true}` when the request is well formed. The raw token is never in the HTTP body.

With no SMTP configured, the token is appended to `data/door-outbox.log` (mode 0600, gitignored). Only a hash is stored in `auth_tokens`. `POST /api/auth/reset` with `{"token":"...","password":"..."}` sets the new password and bumps `sessionVersion`, so older session tokens stop working.

## What P0 does not do

No `door.sys`, no telnet/RLogin, no offline PvP, no player mail. Forest fights use the door combat profile (d20 + attribute versus AC, on the character's HP, gold, and XP). They do not open a Veilspan room combat instance. The classic command loop is unchanged when the session hook is off.
