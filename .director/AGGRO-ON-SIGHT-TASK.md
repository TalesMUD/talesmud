## Engine (generic, Go core; packs opt in through enemy data + ruleset)
1. **Ruleset** `combat.aggro_on_sight`: `enabled` (bool, default true), `grace_seconds` (default 2.5, clamp 0.5–10), `max_level_gap` (default 5: skip players whose level > enemy level + gap; 0 = no level filter), `reaggro_cooldown_seconds` (default 15, per player+NPC after a fight between them ends or after the player fled/left, so flee/re-enter doesn't loop instantly). Follow how `regen.*` / `combat.pacing` are parsed, defaulted and validated; document in docs/COMBAT-BALANCE.md + FEATURES.md + the content ruleset comment.
2. **Trigger**: when a player enters a room (any move path incl. login/spawn into room, respawn, teleport) and when an aggressive NPC spawns/respawns into a room with players already standing there, schedule a grace timer per (player, npc) pair. On fire, re-check everything; if still valid, start combat through the **same path as a manual engage** (`CombatController.InitiateCombat` or whatever `attack` uses), with the NPC as aggressor, so pack/swarm pull, party pull-in, onAggro (exactly once via HookOnce), attackSpeed, summons etc. behave identically. Post one short room line to the target first, Veilspan clipped voice, e.g. "The <name> spots you." (generic engine string is fine; keep it short).
3. **Skip / cancel** (checked at schedule AND fire time): ruleset disabled; NPC dead, not an enemy, not aggroOnSight, already in a fight, or a summoned add; player not in that room anymore (left during grace = escaped), already in combat, dead/ghost/defeated/respawning state, disconnected/not playing, in a dialog/shop if there is such a state cheaply detectable (optional); safe room if the engine has a per-room safe/no-combat concept (find it; `combat.safe_room` in ruleset is the respawn policy, not this — only use a real room flag if one exists); level gap; reaggro cooldown. Guests are normal players (they CAN be aggroed). Party: target is the entering player; party members are pulled in exactly as a normal engage does (no extra logic). If several aggressive NPCs see the same player, only one engage happens; the rest join via normal pack/assist rules or are skipped because the player is now in combat. No goroutine leaks: timers cancel cleanly; work must run on the game loop/whatever lock the combat controller expects (no data races — run `go test -race` on the touched packages).
4. **Tests**: fires after grace; leaving during grace cancels; already-in-combat skipped; dead/ghost skipped; disabled ruleset skipped; level gap skip and gap 0; cooldown blocks immediate re-aggro after flee; onAggro fires exactly once (aggro path and manual path equal); party pulled like manual engage; two aggressive NPCs → one fight; NPC spawn into occupied room schedules. `go test -count=1 -timeout 20m ./pkg/...` green, plus `-race` on the touched packages.
